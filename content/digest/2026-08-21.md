#### 1）今天最值得关注

**[LMSYS 在 H20 上逼近 B300 性能服务 DeepSeek-V4-Pro]**
- **发生了什么**：LMSYS 团队针对 1.6 万亿参数 MoE 模型 DeepSeek-V4-Pro，在 H20 GPU 上通过场景化服务配置优化，单节点 H20-141GB 达到 271 output tokens/s，与 B300 的 383.7 tokens/s 性能差距缩小至 1.42×。
- **为什么重要**：H20 仍是广泛部署的 GPU，该工作证明通过系统级优化（Prefill 与 Decode 分离、Humming MXFP4AFP8 量化、Online C128 KV 扩展、DSpark 投机解码）可以显著缩小与旗舰硬件的差距，对预算受限的团队有直接参考价值。
- **我的判断**：这是长期趋势——模型规模增长快于硬件迭代，系统优化成为"第二增长曲线"。不是短期噪音，值得 SaaS 团队关注部署成本优化。
- **关键数据**：单节点 H20-141GB 达 **271 output tokens/s**，B300 为 **383.7 tokens/s**，性能比 **1.42×**；Prefill 可达 **8.45k input tokens/s**，1M token 提示处理时间 **43.7 秒**；Throughput 模式 DP16-EP16 达 **4.67k output tokens/s**，平均 TPOT **27.4 ms**。
- **来源**：[LMSYS：Blog（Chatbot Arena 团队）](https://www.lmsys.org/blog/2026-08-19-deepseek-v4-pro-engine-optimization-h20)

#### 2）硬核技术 / 产品动态



- **[Mistral 推出 Agentic Search：多步检索提升复杂文档查询准确率]**
  - **事实**：通过 search、open、navigate、read、grep 五工具的多步检索循环，让模型在长文档与多来源中查找、定位并验证信息。
  - **看点**：从"一次性检索"进化到"循环验证"，解决 RAG 场景中模型幻觉和遗漏关键信息的问题。
  - **对老大的启发**：如果你的产品涉及文档检索、合同审查、合规查询，Agentic Search 架构比传统 RAG 更可靠。
  - **来源**：[Mistral AI：News（网页）](https://mistral.ai/news/agentic-search)

  - **对老大的启发**：自动化测试、数据录入、跨平台操作类 SaaS 有了新基座模型选择。

#### 3）可执行机会

- **机会标题**：为小团队提供"H20 级成本优化"的 DeepSeek-V4-Pro 部署模板
- **痛点**：DeepSeek-V4-Pro 性能强劲但 B300 稀缺且昂贵，H20 用户缺乏经过验证的优化配置。
- **怎么做**：基于 LMSYS 开源的优化方法（Humming MXFP4AFP8、Online C128、DSpark），打包成 Docker 镜像 + 配置文档，提供低延迟/高吞吐两种 profile 选择。
- **为什么值得做**：H20 存量巨大，许多团队在"用不起 B300"和"H20 性能不够"之间挣扎，有明确付费意愿。
- **最小起步版**：先做一个单节点 H20-141GB 的 DeepSeek-V4-Pro FP8 推理镜像，包含低延迟 profile（batch=1，271 tok/s）和高吞吐 profile（DP16-EP16，4.67k tok/s），附性能对比文档。
