#### 1）今天最值得关注

**Anthropic 推出 Claude Ship：把 PR 审查、修复与审批接入 GitHub**

- **发生了什么**：11 月 23 日，Anthropic 发布 Claude Ship 测试版，一套跑在 GitHub 上的 agent 组合。核心包括 Code Review（已正式可用）、PR Steward（beta）、Claude Approvals（beta）。Code Review 按仓库选择 Quick / Standard / Deep 三档深度审查 PR；PR Steward 负责让 PR 保持绿色，处理失败的 CI 检查、合并冲突，以及来自代码审查工具或其他审查者的评论，每次推送后都会发评论说明改了什么、怎么回滚；Claude Approvals 读取写进仓库的策略文件，在策略允许时自主批准常规变更，否则转人工。
- **功能与计费**：适用于 GitHub 上 Team 和 Enterprise 计划的仓库；按 token 计费，费用随触及的 PR 数量、审查深度和 PR Steward 的投入程度浮动；管理员可为 Code Review 和 PR Steward 分别设置支出限额；开发者侧通过本地 CLI 输入 `/ship` 触发“推送—开 PR—审查—回应反馈”全流程。
- **实施要点（来源所述）**：Anthropic 在公告中建议先用 observe-only 模式运行一段时间建立信心，再从单个仓库起步并设置月度支出上限。PR Steward 每次推送后都会发评论说明改了什么、如何回滚。
- **关键数据**：三档审查深度（Quick / Standard / Deep）；适用于 GitHub 上 Team 和 Enterprise 计划的仓库；按 token 计费；管理员可分别设置支出限额。

#### 3）可执行机会

- **机会标题**：给 Claude Ship 做“审批策略生成器 + 观察期报告”
- **痛点**：Claude Approvals 要求团队把一个自然语言策略文件写进仓库；可用来源未提供策略模板或观察期报表。
- **怎么做**：接 GitHub App，读团队历史 PR 记录，按目录、文件类型、改动行数、是否触及迁移或配置，统计哪些 PR 从未被要求修改就合并了。自动生成一版 Claude Approvals 能直接读的策略文件，再配一个观察期看板：agent 批准了多少、被人工推翻多少、平均合并时长降了多少。
- **为什么值得做**：Claude Ship 按 token 计费，费用随 PR 数量、审查深度和 PR Steward 投入程度浮动；管理员可分别设置支出限额；策略文件写进仓库，可版本化。
- **最小起步版**：先只做一个 CLI 或单体脚本——输入仓库名，输出一个 `policy.md` 草稿（分成“可自动批准”“需人工确认”“禁止自动”三段），附上支撑每一段的历史 PR 统计。不接 GitHub App，不做看板，先让少量团队试写策略。
- **依据来源**：[TechCrunch AI](https://techcrunch.com/2026/11/23/anthropic-launches-claude-ship-letting-ai-agents-review-fix-and-approve-code-changes/) / [AIHOT · X：Addy Osmani (@addyosmani)](https://aihot.news/items/oom14bdotou4ycx1qqm0kwway)
