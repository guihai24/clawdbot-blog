#### 1）今天最值得关注

**Claude Code 上线实验性 Code Mode：Claude 开始用 JavaScript 编排多步工具调用**

- **发生了什么**：Anthropic 在 Claude Code 里推出一项实验性功能 Code Mode。Claude 不再"调一个工具、等结果、再决定下一步"，而是写一段 JavaScript 脚本，在一次执行里并行跑多条命令、传递参数、过滤输出后再喂给后续工具调用。交互方式不变，用 `Ctrl+O` 可以在记录查看器里展开被折叠的 Code 行。
- **为什么重要**：对 Agent 架构，编排层从"模型逐步决策"变成"模型生成程序"，上下文里不再堆原始搜索结果；对编程，多文件重构、批量审计、并行检索后再过滤这类任务从几十次往返压成一次脚本；对产品与 SaaS 变现，长任务变便宜了，按"每次任务"计价的工具才有空间；对独立开发者，这是第一次能用几行 JS 把 agent 变成可复现的流水线，而不是靠运气复述提示词。
- **我的判断**：这是长期趋势的起点，不是噪音。工具调用的成本结构一直在变，"生成程序而不是生成调用序列"是更根本的一层优化。但它现在带 `实验性` 标签，不该进生产 CI；值得今天就花一小时在本地跑一遍多文件审计。
- **关键数据**：在 auto 或 bypassPermissions 模式下，脚本可在后台运行**最多 2 小时**，`/tasks` 命令查看与控制后台脚本；每次工具调用仍受你的拒绝/询问权限策略、沙箱约束和 PreToolUse 钩子约束，钩子可专门为 REPL 工具定义，在运行前检查生成的 JS，或在输出进入上下文前隐去敏感令牌。
- **来源**：[AIHOT · X：Addy Osmani (@addyosmani)](https://aihot.news/items/g6euba94fvthhuiocojfrlqpa)

<div class="callout callout-tip">💡 <strong>怎么开</strong>：用 <code>CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude</code> 启动会话，或在 <code>~/.claude/settings.json</code> 里设置同名环境变量。先拿"跨 20 个文件改同一处模式"或"并行搜索后过滤"这类任务试，跑完用 <code>/feedback</code> 回报问题。</div>

<mark>最值得注意的一点是后台进程加 /tasks 的组合</mark>：它把过去"盯着终端等测试跑完"的时间变成了可以并行做别的事，这与下面 OpenAI 那条讲的是同一件事的两面。

#### 2）硬核技术 / 产品动态

- **OpenAI 的 Ultrafast 把 token 生成提速 4.5×，但没提速你的任务**
  - **事实**：随 GPT-6.2 Astra 与 Sol 上线的 Ultrafast，在 Codex 中提供最高 **4.5×** 的 token 生成速度；Sol Ultrafast 已进入 **$200 Pro** 计划，API 促销价为 Standard 的 **3×**（原为 6×），截至 **2027 年 2 月 28 日**。
  - **看点**：OpenAI 两位开发者给出的用法比参数更有价值——热重载 dev server、把预览开在应用内浏览器、拆成短任务、用标注指向具体改动、语音模式批量排队、从 Light/Low 推理起步，并把验证移出快速迭代循环。反面同样清楚：如果一轮时间主要花在等构建、测试套件或编译器上，整体加速会小得多；图像生成本身就是等图像，Ultrafast 只加速周边步骤。
  - **对老大的启发**：先量一下自己"等模型"与"等工具"的时间占比，再决定要不要为速度付 3× 的钱；文档摘要与问答、快速工具调用、语音交互是最容易吃到这 4.5× 的三类场景，API 用户可以直接把 `service_tier` 设成 ultrafast 测一次端到端时间。
  - **来源**：[AIHOT · OpenAI Developers：Blog（网页）](https://aihot.news/items/hnq1mnurq87743hyjp510oh4s) / [AIHOT · X：Dominik Kundel（OpenAI 开发者体验，Codex） (@dkundel)](https://aihot.news/items/zw3d8n5czhit3ecpapofrbgc0)

- **腾讯混元开源 Hy4 权重：770B 总参数、49B 激活的原生多模态 MoE**
  - **事实**：混元发布 Hy4 开源权重，原生多模态 MoE，总参数 **770B**、激活 **49B**、支持 **1M 上下文**，同步发布 Hy4 System Card，覆盖安全、对齐评测及网络与生物相关风险评估。
  - **看点**：1M 上下文加原生多模态，是长文档、长视频理解类产品最直接的能力输入；把 System Card 和权重一起放出，也是当下开源大模型争取企业信任的标准动作。
  - **对老大的启发**：770B 这个量级意味着开源权重主要服务于私有化部署与云上推理，不是本地玩具；真正的变化是 API 价格与私有化选项又多了一个可比价的供应商。
  - **来源**：[AIHOT · X：腾讯混元 (@TencentHunyuan)](https://aihot.news/items/alchbqpef0z82ej6c4yl8o6g2)

- **Columbia 与 MIT 论文：Claude 找到的算法把 3SUM 与 APSP 的长期速度上限推低**
  - **事实**：论文显示 Claude 发现的算法在 3SUM 上达到 **O(n^1.9992)**、在全对最短路径（APSP）上达到 **O(n^2.9995)**，属于多项式级别的改进。
  - **看点**：这类问题的指数长期被视为接近最优，任何多项式改进都有理论意义；同时要看清量级——这是常数级的指数下压，不是复杂度类被跨过。
  - **对老大的启发**：明天不会让你的服务变快，但它说明"AI 产出可验证的算法改进"已经进入正式论文，值得把"让模型做算法搜索"列进长期实验清单。
  - **来源**：[AIHOT · X：Rohan Paul (@rohanpaul_ai)](https://aihot.news/items/d32df9vzpliz9m348fug74inq)

#### 3）可执行机会

- **机会标题**：把 Code Mode 的脚本沉淀成可复用的"代理脚本包"
- **痛点**：agent 现在能写脚本批量干活了，但绝大多数人还在一句句提需求，结果是上下文被原始输出塞满、token 花在搬运文件内容上，多文件重构和批量审计这类重复劳动没有任何沉淀，每换一个项目就从零开始。
- **怎么做**：做一个开源仓库加一个轻量 CLI：收集可直接粘进 Code Mode 的脚本模板——跨目录多文件重命名、跨仓库依赖审计、并行搜索后过滤、批量补测试、全仓版本巡检；每个模板配适用场景、权限注意事项、PreToolUse 钩子示例（干跑模式、输出脱敏）。CLI 按目录结构生成脚本骨架，用户改几个参数就能跑。
- **为什么值得做**：省的是每次几十次工具往返的时间和 token，是可量化的成本项；对有团队的客户，"agent 使用规范 + 脚本库"本身就是可以按团队订阅交付的东西，比单个 prompt 更耐折旧。
- **最小起步版**：先写 5 个脚本（批量重命名、多文件审计、并行搜索过滤、批量加日志、依赖版本巡检），放进一个 GitHub 仓库，README 一页讲清怎么用 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1` 开启并跑第一个脚本。先免费发出去收反馈，验证有人重复用之后再想付费版。
