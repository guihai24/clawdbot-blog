#### 1）今天最值得关注

**Anthropic 发布 Claude Ship：AI 开始替团队批准代码合并**

- **发生了什么**：11 月 23 日，Anthropic 推出 Claude Ship，一套用于自动化代码审查、修复与审批的智能体组合，目前面向 GitHub 仓库、Claude Team 与 Enterprise 套餐开放。其中 Code Review 已正式可用，新增的 PR Steward 和 Claude Approvals 处于 beta。Claude Approvals 会读取团队写在仓库里的自然语言策略文件，结合 Code Review 结论和自有分类器，直接决定某个 PR 能否合并。
- **为什么重要**：AI 编程工具已经解决了"写代码"，瓶颈转移到了"决定这行代码能不能上线"。对开发团队，这意味着 PR 队列可以用流水线吞吐；对做研发工具和 SaaS 的人，这是一个新品类——**审批策略即代码，策略本身成了可售卖、可审计的资产**。Anthropic 自己在博客里说：Claude Code 团队的大部分代码是 Claude 写的，所以 PR 之后的一切也必须以同样速度推进。
- **我的判断**：这是长期趋势里少见的"权力移交"，短期别全自动。Anthropic 自己也建议先跑 observe-only 模式、先只接一个仓库、设月度消费上限，说明他们对误批的风险心里有数。真正值得马上跟进的不是"要不要用"，而是"你的团队有没有一份能写成文件的审批标准"——没有这个，工具再好也只是把混乱加速。
- **关键数据**：Code Review 已 GA，PR Steward 与 Claude Approvals 为 beta；审查强度分 Quick / Standard / Deep 三档；策略文件以自然语言写在仓库中；PR Steward 会在每次 push 后评论改了什么、以及如何回滚。
- **来源**：[TechCrunch AI](https://techcrunch.com/2026/11/23/anthropic-launches-claude-ship-letting-ai-agents-review-fix-and-approve-code-changes/) / [AIHOT · X：Addy Osmani (@addyosmani)](https://aihot.news/items/oom14bdotou4ycx1qqm0kwway)

#### 2）硬核技术 / 产品动态

- **家用 PC 十几分钟搭一套私有 ChatGPT，教程给出了完整的显存对照表**
  - **事实**：一篇 Hacker News 热帖给出本地 AI 的完整入门路径：Windows 机器装 Unsloth Desktop，下载 4-bit 量化模型，设上下文长度，打开局域网访问，全家可用。作者用 **RTX 5090、32GB 显存**跑 Qwen3.8-27B 的 4-bit 版本，配 128K 上下文，**除下载外耗时 10-15 分钟**，无需终端命令、Python 环境或订阅。完整版 Qwen 约 **56GB**，消费级显卡装不下，所以必须量化；文中给出经验值：**8-12GB 显存对应 9B-12B 模型，32GB 可舒服跑 27B-35B**。同样 32GB 卡上还能跑 Thinking Machines Lab 于 11 月 17 日发布的 **Inkling 2 Mini**（26.4B 参数、Apache 2.0、支持视觉、1M 上下文），推荐文件 UD-Q4_K_XL 为 **17.6GB**，和本文 Qwen 文件差 0.1GB 以内；它是 MoE，**仅 5.4B 参数激活**，剩余权重放系统内存，因此 16GB 卡也能跑。
  - **看点**：真正的门槛不是模型，是"我的卡能跑多大的模型、配多长上下文"这道算术题。作者选择 27B 而非顶格模型，就是为了给上下文留空间——这个取舍比任何 benchmark 都实用。另外他明确表达了对云端厂商的不信任：模型质量在"最新版"里波动、可运行的内容被限制、成本上涨、隐私顾虑。
  - **对老大的启发**：如果你的产品有大量重复的、吃 token 的中低难度任务（数据清洗、批量改写、内部知识问答），先算一笔本地跑的账，再决定要不要继续买 API 额度。
  - **来源**：[AIHOT · Hacker News：AI 热帖](https://aihot.news/items/fwy4khqwz1da53f8zpcqnzulo)

#### 3）可执行机会

- **机会标题**：做一台"显存选型计算器"，把本地 AI 部署从教程变成服务
- **痛点**：今天的本地 AI 教程暴露了真实摩擦——模型该选多大、量化到 4-bit 还是 8-bit、留多少上下文，全靠一张分散的对照表。加上 MoE 模型（只激活一小部分参数、其余放内存）让"显存够不够"的判断更反直觉，普通人根本算不明白。有隐私需求的小公司（律所、诊所、工厂研发）想自建，卡在第一步选型上。
- **怎么做**：一个网页工具：输入显卡型号/显存、用途（写代码、文档问答、批量改写）、预算 → 输出推荐模型 + 量化档位 + 建议上下文长度 + 需要下载的具体文件与体积，并生成一份可直接照做的部署清单。后面接一条付费服务：上门/远程部署内网私有 AI，按次收费。
- **为什么值得做**：省钱是硬需求（token 账单可预期归零），隐私是硬需求（数据不出内网），而这两点在小 B 客户那里比在大厂那里更容易成交。工具本身做免费引流，交付服务收钱，毛利结构干净。
- **最小起步版**：先只支持 5 张常见显卡（16GB / 24GB / 32GB 几档）、3 个模型（Qwen3.8-27B、Inkling 2 Mini、Gemma 4 31B），输出一张表加一份可复制的步骤清单。不接支付，先挂一个"需要我帮你装吗"的邮箱收集表单，跑通 3 单再谈自动化。
