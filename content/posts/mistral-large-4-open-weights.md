紧接着是坏消息。它有 1T 参数。

这两个事实放在一起，才是这次发布的真实形状——能力是真的，门槛也是真的。中间那段"我到底怎么用它"，得你自己算一笔账，而网上大多数讨论都跳过了这笔账。

---

## 放出来的到底是什么

10 月 29 日，Mistral 把代号 Le Chonk 的 Mistral Large 4 挂上了 Hugging Face，两个官方版本加社区量化版，一起放。


![Mistral Large 4 核心规格与双重稀疏架构解析](/images/posts/mistral-large-4-open-weights.svg)
规格先摆出来，因为后面所有判断都从这里长出来：

| 项目 | 数值 |
|---|---|
| 总参数 | 约 1T |
| 激活参数 | 49B |
| 上下文窗口 | 1M tokens |
| 输入模态 | 文本 + 图像（Pixtral 编码器，1.6B） |
| 语言模型结构 | 72 层，隐藏维 6144，64 个注意力头 |
| 稀疏方式 | 128 专家选 4 + 1 个共享专家，每 token 激活 5 个 |
| 许可证 | Mistral Ecosystem Open-Weight License（MIT 衍生，含限制） |

看到"1T 总参数"和"49B 激活"这两行，很多人第一反应是"那不就等于一个 49B 模型"。不完全对，这个误会值得先拆掉。

MoE 的账是这样的：知识存在 1T 参数里，但每个 token 只走 5 个专家，所以**计算量按 49B 付，显存按 1T 付**。算力端拿到了便宜，显存端一点没省。这个错位在后面讲部署的时候会变成一道很硬的墙。

架构上还有两个细节值得看。注意力块用了 MLA（多头潜在注意力）压缩 KV 表示，再叠一个 DeepSeek 风格的稀疏注意力索引器，每个 query 最多选 2048 个 key 位置。也就是**两层稀疏**：一层在专家维度选网络，一层在上下文维度选位置。再加上 3:1 的 RoPE/NoPE 交替，这套组合是 1M 窗口能跑起来的技术前提。

## 它最值钱的不是分数，是"愿意干活"

网络安全是这次宣传的重点。Artificial Analysis Cyber Index 上，Mistral Large 4 拿到 82%，任务是真去复现一个开源软件里的已知漏洞，然后把它修好。


![开源权重模型与闭源模型在安全策略与自主控制权上的对比](/images/posts/mistral-large-4-open-weights-2.svg)
82% 这个数字本身不算惊人。惊人的是 Hugging Face 那篇博客里顺手带的一句：几个闭源前沿模型在同一个测试上接近零分——因为它们拒绝尝试。

<mark>这 82% 里有一半的差距不是能力差距，是许可差距。</mark>

我把这句拆开看：漏洞复现这件事，在模型的视角里跟攻击长得一模一样——读代码、构造输入、触发崩溃。防御方要修漏洞，前提就是先复现它。而闭源模型的安全策略分不清"我在做防御"和"我在做攻击"，一刀切下去，防御方跟着一起被切。

这里有个反转，别误会成"这是个越狱模型"：在 JailbreakBench、StrongREJECT 和 AgentHarm 的恶意提示上，它的平均拒答率**高于任何其他开源权重模型**。它拒的是"帮我做坏事"，不拒"帮我复现一个我要修的漏洞"。Mistral 自己说，内部测试里它在恶意软件分析、漏洞优先级排序、写检测规则上都有用——这三件事它没有被专门训练过。

对你来说，这个差别的实际形状是这样的：半夜两点在处理事故，你让 API 帮你分析一段可疑的崩溃日志，对面回你一句"我不能协助处理恶意代码"。你没有申诉通道，没有工单可以升级，也没有备选。开源权重解决的不是"模型更聪明"，是**这个说不的环节，你可以自己接管**。

<div class="callout callout-info">
<strong>顺便说个容易被忽略的</strong>：API 用户的另一重风险不是被拒，是被断。账号、地区、供应商策略、计费异常，任何一个环节出问题，你的产品当天就停摆。权重在自己手里，最坏情况是变慢，不是变没。
</div>

## 1M 上下文，到底解决谁的痛

如果你接过需要读整个代码库的活，就知道痛在哪：不是模型看不懂单个文件，是你得先决定把哪几个文件喂给它——而这个决定本身就需要你已经读懂了整个项目。


![1M超大上下文带来的优势与潜在成本对比](/images/posts/mistral-large-4-open-weights-3.svg)
1M 窗口把这道工序抹掉了。加上图像输入，架构图、报错截图、白板照片都能直接扔进去，不用先转成文字描述。Mistral 公布的一组数据里，代码 agent 综合指数 49.8%，排在 DeepSeek V4 Pro 和 Qwen3.8 Max 前面；AutomationBench 59.9%，AA-Briefcase 1393 Elo——这两项考的是一整套业务工作流和长周期专业任务，不是单点解题。

不过这些分数都是厂商和平台方公布的口径 ⚠️，测试条件和提示词没公开，我按"参考"而不是"结论"来看。

长上下文还有一个隐藏成本没人愿意提：窗口越大，你要塞进去的东西越多，token 账单涨得比你以为的快。1M 不是免费的自助餐。

## Mistral Large 4 能本地部署吗？先做个除法

如果你说的"本地"是家里那台带 24G 或 48G 显卡的机器，答案是不能。



这里就是前面那个错位咬人的地方：**49B 激活帮你省的是计算时间，不是显存**。所有专家都得在内存里待着，哪怕这个 token 只用到 5 个。

那 GGUF 呢？Unsloth 和 llama.cpp 团队确实做了量化版本，llama.cpp 生态能加载。但"能加载"和"能干活"是两件事——1T 模型即使在 CPU 加超大内存上跑起来，速度也只够做验证 ⚠️（我没有实测，这是我的判断，别当结论）。想拿它当日常工具，得走另外两条路。

## 那半句许可证限制，卡的是谁

许可证名字很长，本质是 MIT 加了一条：对"把模型当服务卖出去"这件事设了限制。

Mistral 没打算禁止你自己用。你在自己公司内部跑它审代码、分析日志、写检测规则，这些是它想让你做的事。它拦的是另一种用法：把权重包一层 API，对外提供推理服务收费。

对独立开发者的实际含义分两种，别搞混：

- 做**内部工具**、给自己团队或自己的产品后台用——大概率没问题。
- 做**对外产品**，用户直接调用你转售的模型推理——需要逐条读许可证原文 ⚠️，我只看过官方摘要，没逐条对过全文。

如果你在做第二种，这条限制比显存那道墙更值得先搞清楚。

## 三条路，和一条判断公式

把选项摆平了看，其实只有三条，加一条你已经很熟的：

| 路线 | 数据出谁的门 | 成本结构 | 适合谁 |
|---|---|---|---|
| 自有机器本地跑 | 不出门 | 一次性硬件投入 | 4bit 下也要几百 GB 显存池，个人基本排除 |
| 云上租多卡 | 出到云厂商 | 按卡时计费，固定开销 | 有持续、高强度任务量的团队 |
| 第三方托管开源权重 | 出到推理服务商 | 按 token 计费 | 想保留切换权、但不想管硬件的人 |
| 闭源 API | 出到模型厂商 | 按 token 计费 | 任务不敏感、要求开箱即用 |

判断公式就一条，自己代入：

每个任务成本 =（卡时单价 × 24 × 天数 + 你的调试时间）÷ 期间实际跑的任务数

租卡的费用是按小时走的，不管你跑不跑。API 的费用是按 token 走的，不跑就是零。所以只有当你的任务密度高到把卡时跑满，固定成本才摊得薄。一天只跑三次代码审计的人，租卡大概率比 API 贵——但贵的那部分，买的是"数据不出门"和"随时能切"这两样东西，值不值你自己定。

反过来讲，做安全审计、事故响应、处理客户机密文档这三类活，我的判断是：边际成本不该是决策的第一变量。

## 想动手，从这一步开始

不用一上来就想部署。先在别人的机器上验证它到底能不能干你的活，跑通了再谈搬回家。

具体路径：Hugging Face 上有 Mistral Large 4 的 collection，官方两个版本和社区 GGUF 都在里面；想省事就用 llama.cpp 生态的客户端加载量化版，想微调就用 TRL——Hugging Face 那篇博客专门写了用 TRL 微调小模型的流程，思路是拿大模型的修复轨迹去训一个小的，这条对做产品的人比直接跑 1T 更有价值。

然后拿一个可验证的任务去测它，别用"帮我看看这段代码有没有问题"这种没法判分的问题。下面这段可以直接复制：

```
任务：在这个仓库里复现一个已知问题并修复它
1. 读 README 和相关 issue，先用一句话复述问题
2. 定位到具体文件、函数、行号
3. 写出能稳定复现的最小步骤
4. 给出 patch，并解释为什么这样改
5. 如果你拒绝执行某一步，请明确指出你拒绝的是哪一步、依据是什么
```

第 5 条是这段模板里最关键的一句。大多数人在测模型的时候只测"它会不会做"，不测"它什么时候不做"——而后者才是你决定要不要换模型的分水岭。跑三个你自己的真实任务，把它拒绝的步骤记下来，你就知道它跟闭源 API 的差距到底在哪，值不值那台机器。

## 最后一句

这次发布真正改变的，不是"开源追上闭源了"这件事——追没追上还得看几个月的实际使用。它改变的是一个很具体的选择权：当模型对你说不的时候，你有没有第二条路走。

如果你的工作里存在"必须有人干、但供应商不愿意干"的活，那 1T 参数也好、租卡账单也好，都只是这道选择题的价格标签。

先别急着买卡。先拿上面那段模板，去测三个你自己的真实任务。

## FAQ



Q: 开源权重是不是就等于免费使用？<br>
A: 不等于。权重免费下载，但跑起来要机器。许可证是 MIT 衍生，额外限制了把模型包装成推理服务对外售卖，自用和内部工具一般不受影响。

Q: 它的安全能力比闭源模型强吗？<br>
A: 分场景。漏洞复现加修补拿到 82%，而部分闭源模型因拒答接近零分——差距一半来自许可策略。普通编程任务上它排在开源第一梯队，不是全面领先。
