这个月，Anthropic 一位招聘经理，悄悄把「手撕代码」从自己团队的面试里拿掉了。

动手的是 Felix Rieseberg，Anthropic 资深经理（公开信息），带过 Claude.ai 和 Claude Code 桌面版的工程团队，之前还管过 Electron。他配了篇长文《Hunger beats tenure（饥饿感胜过资历）》，写的是给「没有地位、没有话语权的工程师」的建议。帖子发出去，程序员圈炸了。

先说标题里那个最具体的部分，因为它是整件事的引子。我觉得值得注意的，不是「取消手撕代码」本身——那只是一个团队的动作——而是它背后的原因。

Anthropic 内部，大家用 Claude Code 用得太顺手，顺手到觉得它该有个图形界面。于是两个入职不久的工程师——Anthony Morris 和 Alice Zhao——一个周末做出了可用的原型，大约八天后第一个公开版本就上线了。没错，你现在打开 Claude Code 桌面应用，它的起点就是那个周末。

Felix 的原话大意是：再让候选人做一道小 React 题，跟考汇编已经没什么区别了，Claude 两样都比你强。

## 两个故事，看懂「做东西」为什么不再稀缺

Felix 长文里最值钱的不是观点，是两个故事。

第一个发生在 Notion。当年他面试时，有一道题是设计离线模式架构。结果被告知这是道「陷阱题」——因为内部普遍觉得离线不可能实现。理由有两条：数据模型太复杂没法整体同步（这条是真的）；CEO 不可能接受只下载单个页面（这条没任何人核实过，属于内部共识）。不知道内情的新人只想做一件事：去问。

第二个故事更短。Felix 刚进 Notion 时，想给团队装大屏显示实时看板。他撞了组织的墙，失败了，也没力气再去争。一年以后，新人 Ji Pei 带着同一个想法入职。Felix 不以为然地说：别试了，我试过。但 Ji Pei 已经去问了。电视第二天装上了。

Felix 写道：「那一年里的某个时刻，我成了那个老油条。」

两个故事放一起，结论其实很平：不是新人比你更能写代码，是「把想法变成能跑的东西」不再贵了。以前你有个想法，要拿资历证明它靠谱，因为证明很贵；现在，一个周末就能把证物做出来。

## 一对看似矛盾的数据

十月中旬，Anthropic 有一份内部雇佣报告，数据是媒体转述的，我没见过原文 ⚠️，先标着。内容大致是：技术部门里初级员工占比从 21% 降到 14%；新招的人里初级岗占比从 27% 降到 9%。

乍一看，这和 Felix 那种「新人机会很大」的乐观完全相反：公司还在招人，但初级岗在收缩。

但把两件事放在一起看，我判断它们是同一个原因的两个结果：因为「做」变便宜了，一个人能干过去一个组的活，所以个人杠杆上升——这是新人拿着周末 demo 就能飞越老工程师的原因；也因为同样这个原因，公司不再需要那么多「初级执行岗」——这是招聘占比降到 1/3 的原因。杠杆升、坑位缩，不是矛盾，是同一条线的两头。

（补一句省得误会：报告说的是占比——技术招聘总人数还在涨，只是销售、财务这些职能涨得更快；占比降不等于绝对人数同比例减少。而且这是单一高速成长公司的样本，别直接外推全行业。）

## 取消编程面试之后，考什么？

![老闸口与新闸口：证明方式对比](/images/posts/anthropic-drops-leetcode.svg)

这是 Felix 自己都没答上来的问题。他的原话大意是：我还没想明白怎么面试「会用 AI 做事的人」，现在就是翻简历和作品集，找那种「体现品味、同理心、有原则思考」的小原型。

他同公司的另一位平台工程负责人 Katelyn Lesse 最近写了篇文章，谈工程师接下来要解决的新问题 ⚠️（我的转述，没读全文）：AI 把中间那段「边界清晰的执行」压缩掉了，剩下值钱的是两头——上游，决定解决什么问题；下游，保证系统可靠、可控、能被叫停。

我判断，这两头就是「取消 LeetCode 之后考什么」的答案：不是玄学品味，是两样可验证的东西——你做的决定对不对，你交付的东西能不能信。判断力和可靠度，都是平时就能看到痕迹的。

## 好消息和坏消息

**好消息，跟在职的人直接相关。** 第一，你的工作被「看见」的方式变了：过去证明价值靠简历、PPT、等晋升，现在一个能跑的 demo 就是新证物，而做它的成本历史性地低。第二，新的评价标准——判断、同理心、敢不敢开口——全是上班就能练的，不用任何组织批条子。

**坏消息有三条，都有出处。** 第一，「做出来」便宜了，「被听见」没有。Ji Pei 和 Felix 的差别就一句话：他问了，Felix 不问了。公司还是那些层层审批，绿灯还是握在少数人手里。第二，初级坑位在缩，光有「饿」不够——如果你能带的东西只是执行速度，你恰恰是正在被压缩的那一层。第三，新门槛还没立住：旧题撤了，考什么悬而未决，连 Felix 都在「找答案」。这个空档期里，能拿出 demo 的人最稳。

## 那具体怎么办

先自查你在哪一层，再决定用哪只手。

一层：做不出来。→ 用「做」的手。
二层：做出来了，但没人看。→ 用「问」的手。
三层：你自己开始说「这事不可能」——先核一下常识。

**做这一手，周末 prototype 三问**：一，它绑在业务真正要解决的问题上吗？二，能不能一句话说清？（不能，多半是三个好想法埋在一堆坏想法里，这是 Felix 点名的新人最常见错误）三，做完给谁看？答不上来的别做。

**问这一手，两条**：带去找隔级（你老板的老板），别等「做完」——demo 就是论据，配一句话：它能做什么、证明了什么、下一步想要什么。被拒之后别跟组织较劲（那是 Felix 的教训），也别就此不问（那是 Ji Pei 的做法）。

**常识核实这个习惯**：每次心里冒出「这个不可能」「一向这么干」，花十分钟拿模型核一下：这是承重墙，还是只是没人再查过的老规矩？Notion 那个「离线不可能」就是第二种，被一个不知情的新人拆掉了。

## 最后一句

那台大屏第二天就装上了。Felix 和 Ji Pei 的差距，不在能力，在一个「问」。

这个窗口能开多久我说不好——新的证明方式一旦固化成另一种「题库」，又是一轮新的准备。但「用 demo 核实一个常识」这件事的成本，已经被永久性打下来了，这部分不会退回去。

今天的最小动作：把一件你一直觉得「想做但做不了 / 领导不会批」的事写下来，然后花十分钟问模型——这个「做不了」，到底是承重墙，还是没人再查过的老规矩。

## FAQ

**Q: 这是不是说明 LeetCode 完全不用刷了？**<br>
A: 只对 Anthropic 的一个团队是。其他公司还没跟，刷不刷看你去面谁。但趋势清楚：手写代码这道筛子，正在被「给我看你能做出的东西」换掉。

**Q: 我不是工程师，这套对我有用吗？**<br>
A: 有用。产品经理的可点原型、运营的一条自动流程，都是 demo。把判断变成看得见的东西，比写进 PPT 便宜。

**Q: 周末 demo 怎么做才算「作品」，不算玩具？**<br>
A: 过三道问：绑不绑业务、能不能一句话说清、给谁看。第三个答不上来的，就是玩具。作品是要有人接着往前推的。
