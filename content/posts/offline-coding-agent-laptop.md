一位住在喜马拉雅山脚的工程师，把 OpenCode、Ollama 和 Qwen 全塞进一台 MacBook，然后拔掉网线跑测试。

这事听起来像个周末玩具。但我看完他的记录后，觉得最值钱的不是那套配置步骤，而是他无意间划出的那条边界：**哪些活断网能干，哪些活一断就死**。

那条线的位置，可能会让你重新理解"本地模型"这四个字。

---

## 谁真的需要断网写代码？

先说清楚，这件事不是给所有人准备的。它解决的是一个很具体的问题：**你的工作流被"必须有网"这件事绑住了**。


![离线编程的三类核心人群与痛点对比](/images/posts/offline-coding-agent-laptop.svg)
三类人被绑得最紧。

<table>
<tr><th>人群</th><th>痛点</th><th>离线代理能解决什么</th></tr>
<tr><td>网络不稳的人</td><td>高铁、飞机、山区、老小区，断流是常态</td><td>把"没事干的两小时"变成"能推进的两小时"</td></tr>
<tr><td>不想为补全付费的人</td><td>按 token 计费，写得越多账单越高</td><td>电费换 token，边际成本趋近于零</td></tr>
<tr><td>代码不能出本机的人</td><td>客户代码、内部项目、合规要求</td><td>请求根本不出网卡，这是最硬的需求</td></tr>
</table>

第三类人往往被忽略，但他们的需求最刚性。云端模型再强，"把代码发给别人"这一步就过不了审。

我判断，前两类人是在"省钱省时间"，第三类人是在"能不能用"。

## 断网后，编码代理到底还能干什么？

答案取决于一件事：**这件事需要的知识，是不是已经在你硬盘上**。


![离线编码代理能力边界对比图](/images/posts/offline-coding-agent-laptop-2.svg)
先看能干的。项目已经在你本机，依赖装好了，测试能跑起来，那么下面这些活全部可在断网状态下完成：

- 让代理解释一段你没见过的函数，理清调用链
- 定位一个失败的测试，读日志、改代码、重跑，直到变绿
- 小范围重构，比如拆函数、改命名、抽公共逻辑
- 补完一个功能的骨架，让它先跑通再打磨

不能干的也很明确：装新依赖、查某个库的最新文档、翻 GitHub issue、调任何外部 API。这些活的答案不在你的磁盘上，在别人服务器上。

这条线很有意思。同样一句"帮我修一下这个报错"，结果可能天差地别：如果报错是断言失败，代理能自己跑测试、看输出、改了再跑；如果报错是"找不到某个包"，它只能干瞪眼，因为解决方案在 npm registry 里，不在你的仓库里。

**所以离线能力的天花板，是硬盘画的，不是参数量画的。**

<div class="callout callout-info">
💡 <strong>一句话记住这个判断</strong>：离线编码代理不是"弱化版的云端代理"，它是"只吃本地知识的代理"。判断一个任务能不能离线做，别问模型行不行，问这个任务需要的资料在不在本机。
</div>

离线编码代理能完成什么，取决于三样东西是否已经在你本机：模型权重、项目依赖、测试工具。三者齐备时，解释代码、定位失败测试、小范围重构都能在断网状态下完成；缺任何一样，代理就会卡在一个它无法自行解决的环节上，因为它拿不到外部的包、文档或 issue。换句话说，离线能力的上限不是由模型参数决定的，是由你出门前准备了什么决定的。

这个结论有个直接推论：**离线可用性是可以提前投资的**。出门前多花十分钟装依赖、拉文档、把测试跑通，断网时能干的事就多一大截。后文那份检查清单，就是从这个推论长出来的。

## 最小配置：三个组件，四件事

整套东西就三个角色。


![本地AI开发环境的三组件架构与配置要点](/images/posts/offline-coding-agent-laptop-3.svg)
Ollama 负责在本机跑模型，把推理服务挂在 `127.0.0.1:11434`。OpenCode 负责和你的项目交互，读文件、提修改、跑命令。Qwen 是那个被跑起来的模型。

原文用的是 OpenCode 1.19.4 加 Qwen3.5 9B，在 Mac 上。选 OpenCode 的理由挺实在：它留在终端里，不用切窗口，而且自带权限确认——改文件、跑 shell 命令之前会先问你。

配置文件 `opencode.json` 是这套东西的开关面板。你不用抄全量，但必须动这四件事：

1. **模型指向本地**：`model` 和 `small_model` 都设成 Qwen3.5 9B，baseURL 指向 Ollama 的本地端口
2. **只留本地 provider**：把云端供应商关掉，免得它偷偷发请求出去
3. **屏蔽 web 工具**：断网环境下这些工具只会制造超时和误判
4. 保留权限确认：改文件、执行命令前必须弹确认

示意大概长这样（字段名以你装的版本 README 为准）：

```json
{
  "model": "ollama/qwen3.5:9b",
  "small_model": "ollama/qwen3.5:9b",
  "provider": { "ollama": { "baseURL": "http://127.0.0.1:11434/v1" } },
  "tools": { "web": false }
}
```

启动 Ollama 时还要用环境变量把它锁在 localhost，并关掉云端转发功能。这一步很多人会漏，结果模型服务默认对外监听，等于给自己开了个后门。

## 为什么是 9B，不是 4B？

因为在 agent 场景里，函数调用能力比代码生成能力更关键。

Qwen 官方模型卡给了两个榜：LiveCodeBench v6 测代码生成，BFCL-V4 测函数调用。9B 在两个榜上都强于 4B——但真正决定 agent 能不能干活的是后者。

原因不难理解。一个编码代理的循环是：读文件 → 决定调哪个工具 → 传对参数 → 看结果 → 再决定下一步。任何一环参数传错，整个循环就歪了。代码写得再漂亮，工具调不明白也白搭。

所以选本地模型时，我的建议是：先看 BFCL 这类工具调用评测，再看代码榜。这个顺序很多人是反着来的。

有个数字值得单独拎出来说。一篇叫《The Scaffold Effect in Coding Agents》的预印本研究，拿 OpenCode、Goose、OpenHands-SDK 在 50 个 Terminal-Bench Pro 任务上做了对比，发现 OpenCode 每解决一个任务消耗的 token 大约是 Goose 的 40 倍。

40 倍。这个数字在云端意味着账单，在本地意味着等待。同一个指标，两种痛法。你要是习惯了云端 API 的响应速度，第一次在笔记本上跑长任务，会明显感觉到节奏变了。

不过研究也提醒，多数通过率差异在统计上并不显著。而且那批测试用的是云端模型，不能直接推到本地 9B 上。

## 真正跑起来会踩的三个坑

第一个坑是速度。9B 模型在笔记本上生成，和云端旗舰不是一个量级。原文没给具体秒数，但任何跑过本地推理的人都知道，长文件的重构会明显变慢。应对办法是把任务切小：与其说"重构这个模块"，不如说"把这个函数里的三个分支抽成独立函数"。

第二个坑是上下文。64k 听起来够用，但一个中等项目的关键文件加起来很容易超。代理看不到的文件，等于不存在。所以提问时要主动指路："看 `src/parser.ts` 第 80 行开始那段"比"帮我找找哪里有问题"有效得多。

第三个坑是权限确认。这个反而是好事。云端模型犯错，你重新生成一次就行；本地 9B 犯错率更高，而权限确认让你在它执行 `rm` 之前拦下来。在离线场景里，这道确认不是碍事的弹窗，是你唯一的刹车。

<div class="callout callout-tip">
💡 <strong>任务切分比模型选择更重要</strong>：同一个 9B 模型，喂它"帮我改好这个功能"大概率翻车，喂它"这个测试为什么失败，只看不改"往往能给你有用的线索。本地代理的正确用法是当侦察兵，不是当施工队。
</div>

## 出门前 10 分钟 warm up 清单

这份清单是本文最该抄走的东西。它的逻辑很直白：离线能力由本地知识决定，那就在有网的时候把知识搬进来。

- [ ] 依赖装全：`npm install` / `pip install` / `cargo fetch` 跑一遍，确认 lockfile 是干净的
- [ ] 测试能跑通：至少跑一次完整测试套件，确认没有需要联网的用例
- [ ] 模型已拉取：`ollama pull` 完成，并且本地试跑一次，别等到飞机上才发现没下载完
- [ ] 配置文件复查：web 工具已关闭，云 provider 已禁用，baseURL 指向 127.0.0.1
- [ ] 项目索引就绪：如果代理依赖索引或缓存，提前生成一次
- [ ] 文档本地化：常用库的 README 和关键文档存一份到本地
- [ ] 降级预案：把内存预算写下来，知道什么时候该切到 4B

照着做完这七条，你就把"能离线干的事"这个集合撑到了最大。

还有个容易忘的：先断开网络试一次。别等真到了没网的地方才第一次跑，那时候出问题你连搜索都没法搜。

## 最后一句

这套方案不是用来替代云端模型的。它替代的是"断网时什么都干不了"这个状态。

真正的价值可能在于：当你不再把"有没有网"当成开工的前置条件，你对工作地点的选择就多了一点自由。喜马拉雅山脚也好，绿皮火车也好，只要硬盘里的东西够，你就能推进。

我很喜欢这个方向——不是因为本地模型多强，恰恰是因为它不够强，才逼你把任务想清楚再交出去。

## FAQ



Q: 离线编码代理能替代 Claude 或 GPT 吗？<br>
A: 不能。它替代的是"断网时无事可做"的状态，不是日常主力。装包、查文档、调外部 API 这些活，断网状态下依然做不了。

Q: OpenCode 和 Aider 该选哪个？<br>
A: 想要终端里完整的 agent 循环——读文件、改代码、跑测试——选 OpenCode；想要引导式逐段编辑选 Aider。两者都支持接 Ollama 本地模型。
