假设你每天都在重复同一套动作：打开网页、复制编号、填进后台、下载附件，再把文件拖进某个文件夹。做到第三遍时，人已经开始像一台漏电的复读机；做到第十遍时，你甚至懒得骂它，只会盯着屏幕发呆。

现在 AI 不只会给你一段操作说明，它能真的移动鼠标、敲键盘，甚至启动终端。更关键的是，你能在旁边看着它干，随时接手。

我更在意的不是它画出的狗有多像，而是这件事突然把一批「必须盯着电脑做」的活，变成了可以交给 Agent（能自主调用工具执行任务的 AI 助手）的活。

## 画一只狗，为什么比跑分更重要？

这次引起关注的案例来自 Reddit 的 LocalLLaMA 社区。作者使用 QFN 3.8 NVFP4 模型，通过新版 Open WebUI 0.13.0 控制 Open Terminal 0.17.2 提供的虚拟桌面，让模型在 MS Paint 里用鼠标坐标徒手画了一只狗。


![AI 电脑操作 Agent 的完整闭环工作流程](/images/posts/ai-desktop-agent-automation.svg)
关键不在「用 Python 生成图片」，而在操作路径：模型没有直接产出一张 PNG，而是通过界面一步步移动鼠标、按下和松开按键，再观察画面变化，继续修正。

原始案例还展示了两个容易被忽略的能力：

- 虚拟桌面可以运行在浏览器里，操作过程可见；
- Agent 工作时，人可以随时接管，继续引导下一步。



这条演示真正推翻了很多人对 AI 电脑操作的旧想象。过去我们说「AI 会用电脑」，往往意味着它生成一串点击步骤，或者写一段自动化脚本。现在更接近完整的闭环：

```text
观察屏幕 → 判断下一步 → 操作鼠标或键盘 → 读取新画面 → 修正动作
```

模型不必先拥有正确的代码，只要能看见操作结果，就能边做边试。画狗看着不实用，却证明了一件更实用的事：**那些软件里没有开放 API、只能靠点击完成的流程，也能被 Agent 接管。**

## 哪些工作真的适合交给桌面 Agent？

不是所有电脑任务都值得自动化。选错任务，相当于花钱请了一个动作很快、方向感随机的实习生。


![桌面Agent适用的五类任务分类图](/images/posts/ai-desktop-agent-automation-2.svg)
我会用三个问题筛选：

| 判断项 | 适合自动化 | 暂时不适合 |
|---|---|---|
| 重复性 | 步骤基本固定，描述清楚就能复现 | 每次都要根据复杂语境重新判断 |
| 可观察性 | 操作结果能通过屏幕或文件核对 | 错误只在后台悄悄发生 |
| 可逆性 | 出错可撤销，或只在副本上操作 | 删除、转账、发送、发布等不可逆动作 |

按这个标准，下面几类任务最适合先试。

### 1. 网页上的重复填表

比如每天从本地表格读取几组公开信息，再录入后台管理系统。Agent 可以打开浏览器、定位输入框、粘贴内容并保存。

这类任务的价值不在「点击得多快」，而在于能持续运行。你去吃饭，它继续把下一批数据填完；回来再抽查几个结果。

### 2. 文件的批量整理与重命名

下载目录里堆着一堆 `final_v2_really_final.pdf`，是每个做内容的人都会遇到的精神污染。Agent 可以按日期、类型或文件名规则，把文件移动到对应目录。

但别一上来就让它碰唯一的原件。先复制一份测试目录，让它只在那里练手。

### 3. 跨应用搬运信息

网页看到一条信息，填进 CRM；桌面下载一个附件，再上传到另一个平台；把表格里的几列复制到日报模板。Agent 最有价值的地方，就是跨应用搬运，而不是某一个软件内部的单点功能。

### 4. 重复检查与截图留档

每个项目交付前，都要打开测试页面、逐项检查、保存截图、生成报告。这类流程步骤固定、结果肉眼可核对，很适合自动化。

不过，「看起来完成」不等于「真的正确」。Agent 可以关闭错误提示、漏掉失败请求，甚至生成一份格式漂亮但内容错误的报告。检查环节仍然要保留。

### 5. 一次性脚本任务

让 Agent 在终端里创建目录、批量重命名、下载公开数据、运行项目里的构建命令，再检查结果。这比让它自由探索整个电脑更可靠。

关键不是不给它终端，而是把工作目录和权限圈定好。让它在一个项目副本里跑，不要默认它能访问整个家目录。

## 用 Open WebUI 搭一个隔离的桌面 Agent

这次案例涉及两个项目：


![桌面 Agent 搭建与调试五步流程](/images/posts/ai-desktop-agent-automation-3.svg)
- [Open WebUI](https://openwebui.com/)：提供模型聊天与工具调用界面；
- [Open Terminal](https://github.com/open-webui/open-terminal)：提供可交互的虚拟桌面环境，让 Agent 能通过鼠标、键盘和终端操作其中。

Open WebUI 0.13.0 的新能力，是让模型通过程序化控制或 Computer Use（让视觉模型观察屏幕并操作界面）驱动完整 Linux 桌面。Open Terminal 0.17.2 则负责承载这套环境。

具体配置项和菜单名称可能随版本变化，操作前应以两个项目当前版本的官方文档为准。但第一轮测试可以按下面的顺序走。

### 第一步：先准备隔离环境

不要把 Agent 直接连接到装着公司文件、邮箱、网银和密码管理器的日常电脑。

优先使用虚拟机，或者一台专门用于测试的机器。虚拟机里只放完成演示所需的软件、测试账号和虚拟文件。涉及 Windows 桌面时，可以参考原帖作者采用 Windows 11 ISO 的做法，但这属于定制路径，不是官方唯一方案。

这一步的原则很简单：**Agent 的破坏范围，不能超过你愿意重新做一遍的工作量。**

### 第二步：连接模型与虚拟桌面

在 Open WebUI 中选择支持工具调用或 Computer Use 的模型，再连接 Open Terminal 提供的桌面会话。模型名称不是唯一门槛，能否正确输出鼠标坐标、键盘事件和工具调用更重要。

本地模型也并非天然更危险或更安全。模型在本地运行，只意味着数据和推理不必全部离开你的机器；它仍然可能误点、误解和执行危险命令。真正的边界来自权限，而不是模型部署位置。

### 第三步：先让它画一只狗

别一上来就让 Agent 整理整个下载目录。用一个完全可逆的任务测试整条链路：

> 在 MS Paint 中画一只简单的狗。可以自由使用鼠标和键盘，但不要执行安装软件、访问网络或删除文件的操作。每完成一个明显步骤，描述你观察到的画面；不确定坐标时先截图确认。

这个任务同时检查了四件事：模型能否看见桌面、能否执行鼠标动作、能否读取操作结果、能否在不确定时停下来。

如果它把工具栏点乱、线条画偏，但最终能根据画面修正，说明基本链路已经成立。画面不好看只是审美问题，不影响这次测试。

### 第四步：观察完整操作轨迹

桌面 Agent 的调试方式不该只是看最后结果。你需要看到它：

1. 当前看到了什么；
2. 准备执行什么动作；
3. 动作后画面发生了什么变化；
4. 为什么决定继续、停止或请求接管。

Open Terminal 可以在浏览器中交互，这正是它比纯后台执行更适合个人用户的地方：<mark>你不必全程盯着，但必须随时能看见它正在做什么。</mark>

### 第五步：加入人工接管点

不要等它把整份文件处理完，才检查它有没有把合同也归档到「图片」目录。关键步骤前应暂停，例如：

- 删除或覆盖文件之前；
- 发送邮件、提交表单之前；
- 发布内容之前；
- 输入账号、密码或验证码之前；
- 运行来源不明的终端命令之前。

接管机制不是功能失败，而是普通用户使用桌面 Agent 时最实用的保险丝。

## 给 Agent 的权限应该分几档？

最省事的做法是给一个万能管理员权限，然后祈祷模型足够聪明。这和把公司网银密码交给自动化脚本差不多。


![Agent权限分档与操作范围对照图](/images/posts/ai-desktop-agent-automation-4.svg)
更稳妥的权限设计，是让任务越重要，操作范围越窄。

| 任务等级 | 示例任务 | 建议权限 |
|---|---|---|
| 只读 | 查看文件、提取网页信息、生成报告 | 允许读取指定目录，禁止写入 |
| 可恢复写入 | 复制文件、整理测试目录、生成新文件 | 只允许操作副本或指定目录 |
| 外部提交 | 填表但不提交、生成内容但不发布 | 保存前暂停并等待确认 |
| 不可逆动作 | 删除、发送、发布、付款 | 不自动授权，必须人工完成 |

CLI（命令行工具）也应当遵循同样原则。模型需要执行什么，就把能力限制在什么范围。处理图片时只开放图片目录；跑项目测试时只开放项目仓库；涉及凭据时使用环境变量或专门的凭据工具，不要让 Agent 在终端里打印完整密钥。

<div class="callout callout-warn">
💡 <strong>最重要的授权规则</strong>：默认只开放读取能力，写入限定目录，外部提交必须暂停。不可逆动作不要追求「一键自动化」，先追求「人能及时刹车」。
</div>

## 一份可以直接复制的任务模板

先别写「帮我处理一下文件」，这种话和把整台电脑钥匙扔给 Agent 没太大区别。把任务拆成目标、范围、检查点和暂停点。

```text
目标：
把 D:\AgentTest\inbox 中的 PDF 文件复制到 D:\AgentTest\archive。

允许范围：
- 只能读取 D:\AgentTest\inbox
- 只能写入 D:\AgentTest\archive
- 不允许删除、移动或覆盖原文件
- 不允许访问网络
- 不允许运行终端命令

执行规则：
1. 先列出准备处理的文件和数量。
2. 遇到同名文件时停止，不要覆盖。
3. 每处理 5 个文件，检查一次数量和文件名。
4. 完成后生成处理清单，列出成功、跳过和失败项。

暂停点：
- 发现同名文件时暂停并询问。
- 出现任何无法确认的文件类型时暂停。
```

这个模板没有追求「完全无人值守」，而是把任务变成一条有检查点的流水线。对于个人电脑上的第一套自动化流程，这通常比追求炫技更重要。

## 自动化之前，先做一次收益核算

桌面 Agent 的成本不只有模型推理费用，还有搭建环境、维护虚拟桌面、调试提示词和检查结果的时间。

可以用一个简单公式估算：

```text
每次节省时间 × 每月执行次数 × 单次任务价值
减去模型费用、维护成本和出错复核成本
```

只有执行频率足够高、步骤足够稳定，自动化才可能产生净收益。一个每月执行两次、每次只省五分钟的任务，通常不值得专门搭建。

还要注意一个新的风险：自动化会悄悄改变工作方式。原本偶尔手动的流程，一旦接入 Agent，可能每天运行；原本每次都会检查的结果，也可能因为无人复核而长期出错。

所以我更愿意从低风险、高频率的任务开始：复制文件、批量重命名、公开数据录入、测试截图。跑顺之后，再逐步增加写入和外部提交权限。

**桌面 Agent 的价值，不是替你成为更厉害的人，而是把「盯着屏幕重复做」从你的工作时间里拿走。** 但别一开始就让它碰重要文件。先让它在沙盒里画狗、搬测试文件，等你能看懂它的每次点击，再把真正的重复工作交出去。

## FAQ

**Q: Open WebUI 可以控制我的真实电脑吗？**

A: 技术上可以，但普通用户不应直接授权。优先连接虚拟机或专用测试机，只开放任务所需目录；删除、发送、付款等动作应保留人工确认。

**Q: 本地模型运行桌面 Agent，会更安全吗？**

A: 本地运行能减少数据传输，但它不会消除误点和误执行风险。真正决定风险的是系统权限、目录范围、网络访问和不可逆动作的确认机制。

**Q: 普通人最适合自动化哪个任务？**

A: 从高频率、低风险、结果容易核对的任务开始，例如复制文件、批量重命名和测试截图。不要从删除文件、发送邮件或自动发布开始。
