"周报写了吗？领导会的 PPT 呢？"

你盯着 Claude 聊天框，内容已经和模型一起打拉锯战半小时了：需求拆完、数据分析完、金句也想出来了——**真正花你时间的，其实是后面那一公里：复制到 Docs 里排版、再打开 PPT 一页页粘。**

Anthropic 这次干脆承认：用户根本不想管「这是聊天」「那是 Cowork」这种分区。于是它把 Cowork 和聊天合并成一个 Claude，把 Docs、Slides、Design 都接进同一段对话，还让 Claude 自己在后台继续干活。

这篇我就用一个你九成遇到过的场景展开：**周一早上要交周报 + 中午领导会要 5 页幻灯片**，怎么用现在这个「一体化 Claude」从聊天到文档到 PPT 一把梭。

## Claude 这次到底改了什么？

一句话：<mark>你不再需要在「聊天 / Cowork / Design」里选入口，Claude 也不再只产出一堆文字，而是能在同一段对话里直接生出可协作的 Docs 和 Slides，还会在你关掉电脑后继续做。</mark>


![Claude 功能升级的核心三大改进](/images/posts/claude-docs-slides-one-chat.svg)
具体可以拆成三块：

1. **Cowork + Chat 合并成一个 Claude**
   - 以前：  
     - 聊天：临时问答、短任务  
     - Cowork：项目、Artifacts、长任务（要多轮迭代）
   - 现在：  
     - 一个入口，Claude 自己判断这是「随口一问」还是「大项目」，你无需提前分类
     - 你在旧 Cowork 里的项目、聊天、Artifacts、connectors、skills 全都原地保留，只是统一到 Claude 内

2. **Docs / Slides / Design 进对话**
   - Claude Docs：在对话里直接生成结构化文档，可协作、可评论、可分享，能下载成 Word / PDF
   - Claude Slides：从同一轮对话里拉内容，起草演示文稿，在线演示或导出 PowerPoint / PDF
   - Claude Design：之前独立的视觉工具，现在可以在对话里直接用（做封面图、流程图之类）

3. **持续执行：关掉电脑它也干**
   - 你可以给 Claude 一整段复杂任务（"查数据 → 写报告 → 做 5 页 PPT"）
   - 电脑关了、网页关了，Claude 仍然会在云端跑完
   - 你可以选择它「每一步都问你」还是只在关键点提醒

现在的问题就变成：**怎么把「周报 + PPT」这一套交给它做，而不是让它只当输入法？**

## 周报和 PPT 一起做，Claude 要怎么下指令？

### 用一句话把「文档 + 幻灯片」绑定在同一轮


![Claude 协同生成周报与幻灯片的双任务流程图](/images/posts/claude-docs-slides-one-chat-2.svg)
先说核心窍门：**用一段指令，把「报告 + Slides」当同一个任务描述清楚，让 Claude 知道这俩是一套。**

你可以直接丢给 Claude 这样一段指令（可复制）：

```text
我们每周一要出一份销售周报和一套领导会汇报幻灯片，现在帮我一起做完并保持内容一致。

背景：
- 公司：SaaS，做的是项目管理工具
- 本周重点：新签客户 3 家、流失 1 家，正在推进一个大客户的年度续约
- 领导关心：MRR 变动、漏斗关键节点、风险客户

需求：
1）先根据我上传/粘贴的数据写一份「销售周报」，风格保持和往期类似，结构按：
- 本周关键指标摘要
- 重要机会进展
- 风险与应对
- 下周重点计划

2）在报告定稿后，从同一内容生成一套 5 页领导会 Slides：
- 每页一个核心点
- 标题+3~5 个要点
- 和报告里的说法保持一致

3）报告和 Slides 都在 Claude 里生成，可以让我在线编辑、评论后再导出。
```

这里有几个点是关键信号：

- **先说背景 / 领导关心点**，给 Claude 构建一个稳定的「语气 +关注指标」上下文
- 把「报告」和「Slides」写成清晰的 1）/2）子任务，而不是「顺便做个 PPT」
- 明确「Slides 内容必须完全来自报告」，避免它另起炉灶

你后面再上传数据表、往期周报样本，它会在同一对话里自动决定：先整理数据 → 写 Docs → 再生成 Slides。

<div class="callout callout-tip">
💡 <strong>提示</strong>：如果你公司有固定周报模板，可以先让 Claude 把那份模板「翻译」成结构化说明（有哪些章节、每节要回答什么问题），以后只要说「按我们那份模板写」就行。
</div>

## 一步步：怎么用 Claude 完成「周报 + 幻灯片」全流程？

### 1. 准备素材：数据、旧周报、会议偏好


![Claude周报与幻灯片全流程步骤](/images/posts/claude-docs-slides-one-chat-3.svg)
最费脑子的不是写，而是「知道要写什么」。这个部分 Claude 也可以帮你收敛。

你的第一轮操作可以是：

1. 把 CRM 导出的上周数据（Excel / CSV）上传给 Claude
2. 上传或粘贴两期往期周报
3. 在对话里补充两条关键信息：
   - 本周有没有特别事件（比如大客户续约谈崩、上线了新价格方案）
   - 领导最近在会上喜欢抓哪类问题（"为什么漏斗转化在掉"、"哪个行业的客户更有钱"）

然后，你给 Claude 一个「整理 + 归纳」指令，比如：

```text
先不要写周报，请你：
1）从数据表里算出本周新增 MRR、流失 MRR、净增长、签约客户数、流失客户数；
2）对比往期周报，总结我们惯用的写作风格（语气、数据呈现方式、标题长度）；
3）输出一份「本周周报写作提纲」，列出你认为需要重点展开的 3~5 个点。
```

预期反馈：

- Claude 回复一段「指标摘要 + 提纲」  
- 提纲结构最好已经和你每天交的模板很接近

这一步的意义是把你脑子里的「隐含规范」变成它能记住的显性规则。后面周周复用这套规则，你的写作风格会越来越统一。

---

### 2. 生成 Claude Docs：把周报写成「能交的版本」

当提纲看着差不多了，再让 Claude 正式起草周报：

```text
现在请根据提纲，生成一份完整的「销售周报」，并创建为 Claude Docs 形式，注意：
- 保持和往期示例相似的语气和结构；
- 各大段落下面用小标题分隔，方便后续评论；
- 数据来源于本次上传的表格，若有无法确定的数据请用「TODO」标注。
```

这一步在新 Claude 里的效果是：

- 对话里会出现一个「文档预览卡片」
- 点进去就是 Claude Docs，可以直接编辑、加评论、分享链接

你的检查流程可以是：

1. 先扫一遍标题和小节结构——看「讲故事的顺序」对不对
2. 然后在 Claude Docs 里用评论功能对有问题的地方加注释，例如：
   - 「这个数字和我们内部仪表盘不一致」
   - 「这里加一句本周特别提到的客户问题」
3. 回到对话，对 Claude 说：  
   「请根据我在文档里的所有评论，统一修改一版周报。评论内容不要出现在最终文本里。」

Claude 会根据你在 Docs 里的批注再跑一轮，给出修订版。这样，你不用反复复制粘贴来回改。

---

### 3. 从同一内容生成 Slides：PPT 逻辑自动跟随周报

周报定稿后，直接在同一对话里下达 Slides 任务：

```text
周报已经基本定稿，现在请基于这份周报生成一套 5 页的领导会 Slides，创建为 Claude Slides。
要求：
- 每一页对应周报中的一个关键段落；
- 标题是一句话结论，下面用 3~5 个要点支撑；
- 所有数字必须来自周报，不要引入新指标；
- 在 PPT 里为每页建议一个简单图表类型，但先只用占位符。
```

Claude 会做两件事：

- 读刚刚那份 Docs，抽取结构和关键句
- 打开 Slides 视图，生成一套草稿幻灯片（你可以在线预览）

你可以像改周报一样：

- 在某一页上用评论说「标题改成更直白的」「去掉行业行话」
- 或者直接对 Claude 说：  
  「第三页太细了，请合并成一句更高层的总结，注意不要丢掉『风险客户』这一点。」

因为 Slides 和 Docs 在同一对话里，你不用担心「PPT 说的和周报不一样」这个经典事故——所有改动都会立刻反映在 Claude 的上下文里。

---

### 4. 手机上看进度：在通勤路上完成最后审阅

Anthropic 这次 rollout 覆盖了 web、桌面和移动端的 Claude App（Pro / Max 用户先上）。所以你可以这样安排节奏：

- 在家里把数据上传、提纲确认掉
- 出门路上打开手机 App，点进刚才那段对话
  - 看 Claude Docs 里的周报初稿
  - 用大拇指在几个段落上敲评论
- 到公司工位，Slides 也差不多好了，只需要最后调整一下标题

一个细节：Docs / Slides / Design 产物本身都有一个可以单独分享的链接，你可以直接扔给同团队的人，让他们进文档协作，非技术同事也不用进 AI 聊天界面。

---

### 5. 设置成「每周自动跑」：让 Claude 每周一自己开工

真正省时间的，不是单次跑通，而是把这套东西变成固定节奏。

Anthropic 在原文里提到：你可以让 Claude 把这个任务设成每周执行一次。对你来说，一个实用的做法是：

1. 先在 Claude 里完成一次完整流程（数据 → 周报 Docs → Slides）
2. 然后在同一对话里说：

```text
请把这次的任务设置成一个「每周一 9:00 自动启动」的例行任务，
规则：
- 从我指定的这几份数据源拉取最新一周的数据；
- 沿用我们刚刚确定的周报结构和写作风格；
- 先生成周报草稿和 Slides 草稿，再发一条摘要给我确认；
- 在我确认前，不要自动对外分享或导出文件。
```

3. 确认 Claude 对「数据源」「触发时间」「需要你确认的节点」理解无误

后面每周一，你只需要：

- 打开 Claude 的通知 / 对话，看它的摘要
- 进 Docs / Slides 做最后审阅
- 一键导出 PowerPoint / PDF 扔进公司系统

<div class="callout callout-info">
ℹ️ <strong>说明</strong>：具体自动化和定时规则在不同地区 / 账号下可能略有差异，细节以 Anthropic 的 Help Center 为准。你可以先从「固定对话 + 固定指令模板」开始，手动触发一阵子，再逐渐依赖它的自动启动。

## 这套流程在哪些场景最好用？

### 什么时候应该用 Claude Docs / Slides，而不是继续手动？


![Claude一体化适配度对比及时间节省分析](/images/posts/claude-docs-slides-one-chat-4.svg)
把一个任务交给 Claude 的标准可以粗暴地写成一张表：

| 任务类型 | 典型例子 | Claude 一体化适配度 |
|---------|----------|----------------------|
| 周期性文本 + 固定结构 | 周报、日报、OKR 复盘 | 非常高：模板稳定、指标规则清晰 |
| 项目总结 + 复盘 | 项目结项报告、Postmortem | 高：多数据源整合，强调逻辑 |
| 轻演示文档 | 5–10 页的业务汇报 | 高：Slides 足够应付，不追求复杂动画 |
| 正式合同 / 法务文书 | 合同、隐私政策 | 中：需要人工严审，Claude 仅适合起草 |
| 重视觉设计 PPT | 年度大会 Keynote | 低：Design 虽能给图，但仍需专业设计师收尾 |

一个经验判断：

- 写作逻辑重要、视觉花活不重要 → 交给 Claude 产 Docs / Slides
- 视觉细节极重要（品牌色、动画、排版） → 用 Claude 做提纲和文案，最后一公里交给专业设计工具 / 人

### 这能帮你省下多少时间？

别指望「零成本 + 零修改」，那不现实。更靠谱的预期是：

- 原来你要花 1 小时写周报：20 分钟想结构 + 30 分钟写 + 10 分钟对数据
- 现在：
  - 10 分钟整理数据、告诉 Claude 背景
  - 10 分钟改它写的草稿
  - 5 分钟让它再润一次
- PPT 部分则从「30–40 分钟」变成「10–15 分钟改标题 + 检查逻辑」

换句话说，你省下的是「低价值排版」和「把内容在不同软件间搬来搬去」这一段时间。

## 现在的限制和坑：哪些事仍然要回 Google Docs？

### 1. 目前仍是付费用户优先、功能在 beta


![Claude协同办公的现阶段三大限制与应对策略](/images/posts/claude-docs-slides-one-chat-5.svg)
根据 Anthropic 公告：

- Cowork + Chat 合并、Docs、Slides、Design 进对话，这些更新：
  - 先在 Pro / Max 计划上 roll out（已有和新用户）
  - Team / Free 计划会随后跟进（具体时间没写死）
  - Enterprise 要管理员手动开，至少提前 30 天通知
- Docs、Slides、Design 在对话内的形态目前都还是 beta，你偶尔会遇到：
  - 格式细节不稳定（比如标题层级、列表缩进）
  - 导出到 PowerPoint / PDF 后，某些字体 / 布局和你预期略有出入



---

### 2. 协作边界：不是所有人都愿意进 AI 界面

虽然 Docs / Slides 链接可分享，但：

- 有的公司对「包含 AI 生成内容的文件」有合规要求，必须在特定系统里存档
- 有的同事一听到「这是 AI 写的」就本能排斥

对此，一个实用的折衷方法是：

1. 在 Claude 里生成 Docs / Slides，内部审阅、迭代都在这里完成
2. 最终版本导出成 Word / PPT，存进公司指定的 Google Drive / OneDrive / 企业网盘
3. 在导出的版本里保留简短一行：「初稿由 Claude 协作生成，数据和结论已人工复核」

这样既享受 AI 的生产力，又不过度挑战组织的「心理安全感」。

---

### 3. 数据源和权限：让 Claude 干活前，先想清楚能看到什么

Anthropic 的例子里提到：有用户让 Claude 去法律数据库里抓案例、下载、归档。对你来说，几个现实问题是：

- Claude 到底能直接访问哪些系统？（通过 connectors / skills 对接，还是你手动上传）
- 哪些数据可以拿出来交给第三方 AI 服务？哪些属于严格敏感？

一个基础做法：

- 用 skills / connectors 只连那些本来就可以导出的业务数据源（BI 报表、脱敏日志）
- 对涉及个人隐私、合同细节的内容，先人工筛过，再上传给 Claude
- 在给 Claude 的第一个指令里明确边界，比如：

```text
你只能使用我在这次对话中上传的文件，不要尝试访问任何外部网址或历史对话中的内容。
```

这句话不会构成「绝对安全边界」，但至少把 Claude 的行为限定在你可控范围内，让后续的审计简单很多。

## 自包含小结：Claude 一体化对个人用户的价值是什么？

对独立开发者和技术职场人来说，这次 Claude 更新的关键点，不是 UI 少了一个 Cowork 按钮，而是：<mark>你可以把一整个「从数据 → 报告 → PPT」的流程交给同一段对话来承接，文档和幻灯片自然保持一致，而且 Claude 能在你离线时继续干活。</mark>这极大降低了「复制粘贴、排版、对齐内容」的机械劳动量，让你把时间花在选择和审阅上，而不是反复搬运。配合每周定时任务，你可以逐步把那些重复性的周报、例会材料，变成 Claude 的长期工作，而自己只做最后那道「拍板」工序。

## FAQ

Q: 没开 Pro/Max 的 Claude 用户，现在能用 Docs 和 Slides 吗？<br>
A: 现在这波一体化功能优先 rollout 到 Pro 和 Max 计划，Docs / Slides / Design 在对话里的用法也在这些付费计划里先开放。Team 和 Free 会随后跟进，具体时间 Anthropic 还没给死线。

Q: 我已经在 Cowork 里有一堆项目了，会不会被迁移搞乱？<br>
A: 不会被丢。原来的 Cowork 内容（聊天、项目、Artifacts、connectors、skills）都会原样保留，只是入口统一到一个 Claude 里。你打开 App 时，会在新的界面上直接接着原来的项目继续干。

Q: 要不要立刻把所有文档工作都搬到 Claude 里？<br>
A: 不必。优先挑周期性强、结构稳定、视觉要求不极端的内容，比如周报、项目复盘、轻量汇报。正式合同、公文等仍推荐在现有协作平台里维护，Claude 主要帮你起草和打磨。
