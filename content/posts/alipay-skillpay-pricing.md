2026 年 7 月，支付宝上线了一个叫 SkillPay 的东西。四个月过去，你在技术群里问一圈，大概率没几个人说得清它是干什么的。

它干的事其实很具体：让别人花钱调用你的 Skill，钱走支付宝。

现在换个视角。你电脑里大概躺着几十个提示词——那个改简历的、那个从 git log 生成周报的、那个给小红书标题做违禁词自查的。它们被改过七八版，稳定得你自己都懒得再动。你也许动过"这玩意能不能卖"的念头，然后卡在同一个地方：卖给谁、怎么交付、怎么收钱、被转发了怎么办。

这条链路上，最难的一直不是内容，是通道。SkillPay 补的是通道。

---

## 先看清一件事：你卖的到底是什么

很多人的第一反应是把它当"提示词商店"，上去挂一段 prompt 收钱。这个理解会让你第一单就做错。


![Skill 与纯文本 Prompt 的契约对比图](/images/posts/alipay-skillpay-pricing.svg)
Skill（打包好的提示词加工具调用，Agent 调用它来完成一类任务）和一段纯文本 prompt 的差别在于**它带输入输出契约**。买家给什么、你返回什么、失败的时候怎么处理，这些都要写死在结构里。纯文本 prompt 是"你自己拿去玩"，Skill 是"我给你一个能跑的东西"。



顺便说清楚门槛：这比自己发文档、卖课的链路短得多。走小报童或知识星球那套，你得先有个"值得付费的人设"，还得持续更新、维护社群、处理退款。挂一个 Skill，你需要的只是它真的能用。

---

## SkillPay 到底是什么？

简单说：支付宝做的一个 Skill 交易平台，支持买断和订阅两种卖法。买断把 Skill 的完整内容交付到买家本地，一次性收费 0.01 到 50 元；订阅不交付内容，Skill 留在云端沙盒里运行，Agent 只能拿到执行结果、看不到明文，按周、月、季度收费，单周期上限 50 元。两种模式都要求提供免费试用，最低 5 次。


![SkillPay 买断与订阅两种模式对比图](/images/posts/alipay-skillpay-pricing-2.svg)
这段话里已经埋了整篇文章的三个关键点：**交付形态决定了防盗版能力，价格上限决定了这不是高客单生意，试用次数决定了你的转化成本压在哪。**

先说交付形态，这是最容易被低估的一刀。

---

## 买断和订阅，差的只是交付方式吗？

不是。这两个选项对应的其实是两种完全不同的生意。


![买断与订阅的模式对比图](/images/posts/alipay-skillpay-pricing-3.svg)
买断把完整内容交到买家手里。好处是买家安心——东西在我这儿，你跑路我也还能用。坏处也很直接：**明文一旦落地，你就失去了对它的全部控制。**对方存一份、打包发到群里、拆开揉进自己的产品，你没有技术手段拦，也没有精力一个个追。

订阅把 Skill 关在云端沙盒里跑。买家付的是"调用权"，不是"内容"。这对高价值 Skill 几乎是唯一讲得通的选择——你的知识库、你的私有数据、你那套调了半年的判断逻辑，都不用交出去。代价是买家会犹豫："哪天你停服了，我买的算什么。"

| 维度 | 买断 | 订阅 |
|---|---|---|
| 交付物 | Skill 完整内容，落到买家本地 | 只有执行结果，明文不出沙盒 |
| 计费 | 一次性，0.01–50 元 | 按周 / 月 / 季，单周期上限 50 元 |
| 防盗版 | 基本为零 | 强，靠不交付明文 |
| 收入形态 | 靠流量，卖一次算一次 | 靠留存，用户不走就有复购 |
| 买家顾虑 | 买到的是不是别人也买到的东西 | 停服、涨价、规则变动 |
| 适合什么 | 结果一眼能验证的窄任务 | 需要持续更新、或依赖你私有数据和 API 的 |

我的判断是，**买断适合当引流款，订阅才适合当主力款**。原因不在道德，在算术：一次性收入的天花板是你这个月的曝光量，而复购收入的天花板是你能不能让同一个买家第二次掏钱。前面那个你控制不了，后面那个你可以。

还有一个更实际的坑，很少有人提：如果你的 Skill 调用的 API 是你自己的 key，买断交付之后，买家跑一次你付一次钱。这种结构只能走订阅，没得选。

<div class="callout callout-warn">
⚠️ <strong>先想清楚谁付推理费用</strong>：Skill 依赖外部模型 API 时，付费方必须是使用方。把"我替你垫 API 成本"的买断款挂上去，等于给自己开一个无上限的信用卡。
</div>

## 从签约到收款：上架四步

公开信息里给的是流程骨架，没给到页面路径那一级，所以下面按"你该准备什么、怎么判断做对了"来写，具体的入口以平台当前页面为准。签约主体能不能是个人的问题，我也没看到明确条款，别拿我的判断当依据。


![上架四步流程图与签约必读三项](/images/posts/alipay-skillpay-pricing-4.svg)
| 步骤 | 你要做的事 | 做完应该看到什么 |
|---|---|---|
| 签约 | 开通支付宝侧的商家或开发者能力，签平台协议 | 拿到能上架的应用身份，看到结算与抽成条款 |
| 封装 Skill | 写清触发描述、输入格式、输出格式、失败处理 | 拿一段陌生需求试跑，它能被正确触发并给出可用的结果 |
| 定价 | 选买断或订阅，设免费试用次数 | 买家视角能看懂一句话：这个东西解决什么问题 |
| 上线收款 | 提交审核，过审后挂出去 | 订单、结算周期、退款规则在后台能查到 |



签约这一步最值得花时间的不是点同意，是读清楚三件事：结算周期多久、退款责任怎么分、平台能不能单方面下架你的 Skill。第三条尤其重要，你的收入建立在一个你无法控制的渠道上。

## 50 元封顶，说明这是一门什么生意

买断 0.01 到 50 元，订阅单周期上限也是 50 元。这个数字不是随手定的，它在告诉你平台想让买家"不用思考就下单"。

所以你的定价锚点不是"我做了多久"，而是**"买家自己写一遍要折腾多久"**。他要花两小时才能调出来的东西，你收二十块，他算都不用算。他要是五分钟能自己写出来，你收五块他也觉得贵。

这条判断会改变你的选品。别做"通用写作助手"——那个买家自己也会写，还能随时改。做那个他调不出来、或者懒得调的东西：格式死板但要求严格的输出、需要一堆规则交叉检查的任务、需要接外部数据的流程。

反过来，50 元封顶也意味着**单款产品不可能养活你**。这不是悲观，是结构。你能做的只有把收入结构从"卖一个贵的东西"改成"卖一串便宜的东西"：

- 一个低价的买断款负责拉新，让别人零风险验证你的水平
- 一到两个订阅款负责留存，靠持续更新和私有能力锁住复购
- 一套统一的命名和描述风格，让买过你第一款的人能认出第二款

说白了就是：第一单的目的不是赚钱，是让买家相信你的第二单。

## 免费试用 5 次，是最狠也最公平的设计

平台要求提供免费试用，最低 5 次。很多人会把这当成成本，想尽办法把试用做得"能用但不够好"。

这是一个把自己坑死的做法。5 次调用在买家那里得到的不是一个模糊印象，是一个结论：这东西到底行不行。你的前 5 次输出质量，就是你的转化率。把它做得勉强能用，等于花钱买差评。

正确的做法反过来：把你的 Skill 设计成第一次调用就能交付一个完整结果。不要设置"先填三个参数再选模式"这种前置，买家在试用阶段没有耐心。他最想要的是把你的输入样例粘进去，然后看见一个能直接用的输出。

有个细节值得琢磨。试用 5 次意味着一个买家最多把你的 Skill 用 5 次就得出判断，这 5 次里你没有任何机会解释、没有客服、没有售前话术。这既是压力也是好事——它逼你把能力做成结果，而不是做成说明。

## 第一件该挂上去的是什么

我给三条判断标准，你拿手里那堆提示词过一遍，能同时满足的通常不超过两个。

| 标准 | 为什么 | 怎么自测 |
|---|---|---|
| 输出能被 30 秒验证 | 试用期没人研究，只会扫一眼 | 把结果给你不懂这行的朋友看，他能说出"这个对/不对" |
| 输入边界清楚 | 边界模糊的 Skill 触发不准，试用就废了 | 你能一句话说清它只处理哪类输入 |
| 你自己一周用三次以上 | 高频说明它解决的是真问题，不是想象的需求 | 翻你的历史对话记录，数一下 |

按这三条过一遍，"帮我写得更高级"这类会被直接刷掉——输出无法验证，边界也不清楚。"从一段会议记录里提取待办、负责人、截止日期，输出成表"就能留下：输入明确，输出能一眼看出对不对，而且你每周开会都用得上。

类似的还有：按一份 JD 改写简历并标出被筛掉的风险点、批量生成标题后自动做违禁词自查、从一堆发票截图里抽出金额和税号成表。共同点是它们都在替买家省一段重复劳动，而不是替买家做审美判断。

一个可以直接抄的 Skill 描述模板，重点在最后两行——大部分人只写前两行，然后在试用期被刷掉：

```
【做什么】把一段会议记录整理成待办清单。
【输入】原始记录文本，可以带口语和错别字。
【输出】表格：事项 | 负责人 | 截止时间 | 缺失信息。
【不做】不猜负责人，不编造截止时间；原文没提到的写「未提及」。
【失败时】输入少于三句话时，直接回复需要更多上下文，不要硬凑。
```

那两行"不做"和"失败时"，是买家判断你靠不靠谱的地方。一个会承认自己不知道的 Skill，比一个什么都能答的 Skill 更像专业工具。

<div class="callout callout-tip">
💡 <strong>描述里少用形容词</strong>：「专业」「高效」「智能」这三个词在试用场景里没有任何信息量。换成"输入什么、输出什么、什么时候不工作"，转化会明显不一样。
</div>

## 该提前想清楚的四个风险

第一个是明文外流，只针对买断款。你没法阻止，只能选择不把值钱的东西放进去。判断方法很简单：这个 Skill 的明文被贴到公开群里，我会不会心疼？会，就别挂买断。

第二个是平台依赖。抽成、结算周期、审核标准、类目规则都可能变，你的收入建在一个不是你的渠道上。这不是让你别做，是让你别把全部收入押在单一平台上——同一套 Skill 描述，改改格式挂到别的渠道，成本很低，值得提前做。

第三个是审核的不确定性。涉及金融、医疗、法律建议的 Skill 会不会被卡，我没看到公开的判定标准 ⚠️。真要做这类，先拿一个低风险的版本试水，别一上来就压重注。

第四个是自己的幻觉。看到 50 元上限会觉得"这赚不到钱"，看到"支付宝"三个字又觉得"这是个大机会"。两个反应都不对。它就是一个低单价、靠规模、靠复购的小生意，值不值得做取决于你有没有已经打磨好的东西——有，边际成本接近零；没有，你要先花两周做内容，那这两周的回报率大概率不如去接一个外包。

## 今天能动手的那一步

不用先研究平台。打开你的对话记录，找那个你这周用过三次以上、每次都要重新粘贴一遍的提示词。

把它补齐三段：输入是什么格式、输出要什么结构、什么情况下它应该说"我不知道"。补完这三段，它就从一段文字变成了一个能交付的东西。

然后挂一个低价的买断款上去。第一单赚多少不重要，重要的是你会第一次拿到一个真实买家在试用 5 次之后的反应——那个反应比你自己推演十遍都准。

## FAQ

Q: Skill 和我平时写的提示词有什么区别？<br>
A: 提示词是给人复制粘贴的文本，Skill 是带输入输出契约、能被 Agent 直接调用的能力包。差别在于它规定了输入格式、输出结构和失败处理，所以能被稳定调用、也能被定价。

Q: 买断卖出去之后，买家能转卖吗？<br>
A: 技术上拦不住。买断会把完整内容交付到本地，之后的分发你无法控制。值钱的东西建议走订阅，把 Skill 留在云端沙盒里，只交付结果。

Q: 没有公司主体，个人能上架吗？<br>
A: 这一点我没看到明确的公开条款，得在签约页按当前要求确认，别拿别人的经验当准。如果你只有个人身份，先看清签约主体和结算账户的要求再决定投入多少。
