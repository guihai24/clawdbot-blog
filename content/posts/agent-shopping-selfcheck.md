你的产品页现在有两个读者。

一个会滚动，会被主图打动，能容忍「详情请咨询客服」。另一个不会滚动，更依赖能提取出来的字段，未必会追问缺失信息。在这类购物任务中，它首先要做的是：把你页面上的内容切成能互相比较的字段，对不上就可能跳过。我管这个叫**隐形筛除**——你未必能从后台分辨这次访问为什么没有进入比较。

**第二个读者正在变多，而大部分小团队还没开始为它改页面。**

a16z 和 The Prompting Company 最近跑了一组测试：1,270 条购物提示词，四个 Agent（Grok Bot、Muse、Instinct、Dots），11,307 次完整流程，跑完再拿 YipitData（一家追踪消费交易数据的公司）的真实消费记录做对照。他们给这件事起了个名字，B2A——business to agent，生意对面坐着的不再是人。

我的判断是，这不是又一轮「AI 电商要来了」的口号，而是<mark>产品页的评价标准被换掉了</mark>。以前你只需要让人相信你，现在还得让一个不猜意思的解析器认得出你。

先说明一件事：我拿到的是报告摘要和测试规模，那五条方法的原文在 a16z 的 newsletter 里。所以下面这套东西不是转述，是我按「Agent 怎么读一个页面」的顺序重建的自查清单。

## Agent 是怎么「逛」你的产品页的？

**它不逛，它筛。** 整个过程是一串过滤，没有哪一步是「随便看看」。


![Agent 七步筛选漏斗与候选集淘汰示意](/images/posts/agent-shopping-selfcheck.svg)
| 阶段 | Agent 在干什么 | 你会在哪一步消失 |
|---|---|---|
| 理解需求 | 把一句话拆成硬约束（预算、尺寸、到货日）和软偏好 | 你的品类没被写成它认识的词 |
| 拉候选 | 用搜索或内置商品库拉一组候选商品 | 你根本不在它默认的检索面里 |
| 抽字段 | 打开页面，抓价格、规格、库存、配送 | 价格在图片里、弹窗里、登录后 |
| 过滤 | 按硬约束砍掉不合格的 | 单位不统一，没法比 |
| 排序 | 剩下的按价格、评分、退货政策排 | 评价数少、政策没写 |
| 执行 | 加购、填地址、付款 | 必须询价、必须打电话 |
| 回报 | 给用户一段总结，说明为什么选这个 | 你的差异点它没提取出来，总结里没你 |

注意最后一行。Agent 交给用户的不是你的页面，是一段三五行的总结：为什么选这个、为什么不选另一个。你如果没被写进那段总结，用户在整场对话里都不会知道你存在过——哪怕你比被选中的那家更合适。

**你不是输在不够好，是输在没进候选集。**

这件事对买家也一样。你让 Agent 帮你挑一副耳机，它给你的三个选项，可能只是「能被读懂的三个」，不是「最好的三个」。你省下了比价时间，也交出了候选名单的控制权。

## B2A 和 SEO 到底差在哪？

SEO 争的是排序位置，B2A 争的是能不能被解析成一条候选记录。排在第一页、价格却印在宣传图里，对 Agent 来说等于不存在。


![SEO 与 B2A 竞争单位对比图](/images/posts/agent-shopping-selfcheck-2.svg)
B2A 的核心变化是流量所有权转移。过去用户点进你的页面，你能控制叙事顺序：先看卖点，再看价格，最后被推荐一个加购。Agent 不按这个顺序读，它只抽取自己需要的字段，把价格、规格、配送时间压成一行，拿去和别家比。你的品牌故事、视觉设计、文案情绪，在这一步几乎不参与决策。所以 B2A 的竞争单位不是「页面」，是「字段」。谁的字段干净、完整、能换算，谁就进候选。

还有一个更微妙的变化：用户停留在页面时，文案还有机会解释产品。Agent 如果只提取指定字段，叙事内容就可能不进入比较过程。

这对独立开发者其实是好消息。你没有预算去拼视觉，但你完全可以把字段写清楚。**这一局比的不是谁更像品牌，是谁更像一张能被引用的数据表。**

## 五道闸：你的页面过得了几道？

| 闸门 | 失败长相 | 今天怎么改 |
|---|---|---|
| 价格能被读出来 | 价格做成图片、登录才显示、只写「起价」却不解释对应配置 | 正文用纯文本写具体价，区间价说清哪个配置对应哪一档 |
| 规格能跨店比较 | 「大份」「一套」却不给准确规格 | 补克数、片数、每单位价格 |
| 库存和到货明确 | 「现货充足」「下单后尽快发」 | 写清实际承诺的发货期限与预计送达范围，不能凭空承诺 |
| 不问人就能下单 | 「请联系客服询价」「批量优惠私聊」 | 至少给一个能直接下单的标准配置和标准价 |
| 身份能对上号 | 同一件货三种叫法，标题堆关键词 | 品牌名加型号保持一致，页面加结构化数据（JSON-LD，嵌在网页里给搜索引擎和 Agent 读的结构化数据） |


![五道闸页面体检清单与优先修复项](/images/posts/agent-shopping-selfcheck-3.svg)
最后一条最容易被忽略。Agent 在不同时间抓两次你的页面，标题从「经典款」变成「升级款」，它会当成两个不同的商品，两个都不给高分；反过来，你把同一件货铺成三个链接，它可能判定为三家店在卖同款，然后只留最便宜的那个。你铺得越多，它越认不出你是谁。

<div class="callout callout-warn">
⚠️ <strong>别急着上工具</strong>：这五道闸大部分不用改代码，改文案和图片位置就能过。先修最贵的那个——通常是没有文本价格。
</div>

## 三个最容易失分的地方

### 第一：价格不是「文本」，就等于没有价格

Agent 的第一道硬过滤通常是预算。用户给出预算，它得先能比较。你的页面只写起价，它可能把最低配置的价格用于筛选，之后才发现用户需要的配置更贵。这一单大概率退货，或者被它在下一步自己纠正掉——你白拿一次点击，没拿到订单。

区间价不是问题，「起」后面没有解释才是问题。把「哪个配置对应哪个价」写成一句话，修改本身不复杂。

### 第二：规格写得像给人看的

「家庭装」「大份」对人是够的，因为人会看图、会看评价、会拿经验补。Agent 不会补。它要跨店比价，就必须能换算。

你只写模糊的包装规格，隔壁给出明确重量和单位价，它更容易拿隔壁的数据作比较；你写「家庭装」，它可能直接跳过，因为没法确定这算多少。它不会来问你——它只会去拿能算清楚的那家。

### 第三：只优化了被选中，没优化被选对

这是最少人提的一点。**被选错的成本，比没被选中更高。**

退货会增加来回运费、处理时间和可能的折损。但报告摘要没有给出这些成本，不能据此估算亏损金额。实际影响要结合你的品类、运费政策和历史退货记录判断。

Agent 只会按用户的字面约束挑，它不知道你的床垫不适合某些身高和使用场景，也不知道你的配件不兼容某些旧款车型。所以页面要主动写一句「不适合谁」：尺寸上限、兼容范围、场景限制。

这看起来像在劝退。实际上人读到会觉得你坦白，Agent 读到会把它当硬约束，提前把错的单子挡掉。

## 今天下午能做的三件事

1. **纯文本测试**。打开你的商品页，全选复制，粘到一个空白文本文件里——Mac 用 `Cmd+Shift+V` 粘成纯文本，Windows 直接粘进记事本。看价格、库存、规格、配送还在不在。缺的，就是 Agent 看不到的。
2. **换身份审一遍**。把纯文本丢给模型，让它扮演下单的 Agent：

```text
你现在是替用户下单的购物 Agent。用户需求：{写真实需求，含预算、尺寸、到货时间}。
下面是我产品页复制出来的纯文本。请只依据这段文字回答三件事：
1）你会不会把我放进候选名单，为什么；
2）哪些字段缺失，导致你无法比较或只能跳过；
3）如果你同时打开了另外两家同类页面，你会拿哪三个数字来排序。
别客气，直接说哪里读不出来。
```

3. 给每个 SKU（商品编号）加一个单位价，加一句「不适合谁」。每片多少钱、每单位重量多少钱、每月多少钱。这一行字的性价比，比改主图高得多。

## 最后一句

你的页面不需要更漂亮，需要更容易被引用。

下一次改落地页之前，先问自己一句：这段话是写给会滚动的那个人，还是写给不会滚动的那个？

## FAQ

Q: B2A 到底是什么意思？<br>
A: business to agent，客户不是人，而是替人办事的 AI 智能体。它自己检索、比较、下单，你面对的是一个解析器加一套决策规则。

Q: 不做电商也要关心吗？<br>
A: 要。任何「被检索—被比较—被选择」的生意同理：SaaS 定价页、外包报价页、课程介绍页。读不到价格和交付范围，就不会进候选。

Q: 现在改，投入大吗？<br>
A: 可以先做纯文本测试，再按缺失字段逐项补齐。真正花时间的是想清楚「我的产品不适合谁」，这句没有模板。
