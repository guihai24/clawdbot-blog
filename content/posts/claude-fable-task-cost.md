模型降价，你的账单应该变小。这是所有人的直觉，也是 Anthropic 这周用一次发布亲手打破的直觉。





---

## 为什么更便宜的模型，跑一个任务反而更贵？

一句话回答：**API 账单算的是 Token，Token 消耗量取决于模型多「勤奋」，而 5.2 比它的前辈勤奋太多了。**


![Fable 5.1与5.2单价对比与任务总成本差异图](/images/posts/claude-fable-task-cost.svg)
看 run log 就明白了。面对同一个专业任务，Opus 5.5 和 Fable 5.1 大概会写 20 个测试用例来验证自己的答案。Fable 5.2 呢？有时候写几百个，甚至上千个，还会拉起 SubAgent（专项子助手）独立检查自己的工作。

这些检查有效吗？非常有效。Fable 5.2 在 GDPx 上拿了 16.4% 的成绩登顶，比前辈高一截。但每一行检查代码、每一次子智能体调用，都是要付钱的。

这里有个很容易被忽略的账本结构。API 计费有两层：

- **单价层**：每百万 Token 多少钱，这是零售价，Anthropic 降的是这一层
- **任务层**：完成一件事总共烧了多少 Token，这是你月底真正付的钱

打个比方，就像餐厅把每道菜的食材单价降了两成，但新主厨坚持每道菜都配五道检验小菜——你结账时发现账单反而厚了。降价是厂商的事，<mark>用量是模型自己决定的</mark>，而你控制不了模型多自觉，只能控制给它什么活、开什么档位。

### 这次更新的定价细节

| 项目 | Fable 5.1 | Fable 5.2 |
|---|---|---|
| 输入单价 | $10 / 百万 Token | $8 / 百万 Token |
| 输出单价 | $50 / 百万 Token | $40 / 百万 Token |
| GDPx 单任务成本 | $67.16 | $88.15 |
| 推理档位 | — | low 到 max 共五档，默认 medium |

顺便一提，输出 Token 的单价是输入的 5 倍。而「写一千个测试用例」这种自我检查行为，烧的恰恰是最贵的输出 Token。这就是为什么涨价集中在任务层——模型的勤奋，主要花在了输出端。

## 档位才是普通人的省钱开关

Fable 5.2 提供五档推理力度：low、medium、high、xhigh、max。App 和 Claude Code 里默认是 medium。


![Fable 5.2 各推理档位任务配置与省钱策略对比图](/images/posts/claude-fable-task-cost-2.svg)
有意思的是官方自己放出的数据：在 FrontierCode 2.0 基准上，<mark>Fable 5.2 开 high 档，做到了 Opus 5.5 开 max 档的效果，单任务成本只有一半左右</mark>。也就是说，上一代旗舰拼尽全力干的活，新一代中档力度就能干，还更便宜。

反过来的教训更狠：别碰 Fable 的 max 档。原话是「别谈 Fable at Max」——连评测者都建议绕开，因为那一档的 Token 消耗没有上限，模型会不停地自我验证。我判断是，max 档留给那种「算错一次损失几万美元」的场景才划算，日常任务用它是用跑车的油钱买菜。

我整理了一张组合表，按任务类型给建议：

| 任务类型 | 建议配置 | 理由 |
|---|---|---|
| 日常问答、改文案、简单脚本 | Sonnet 5.5 或 Fable 开 low/medium | 勤奋的旗舰模型在这种活上是浪费，它仍会做多余的检查 |
| 复杂编码、架构设计 | Fable 5.2 开 high | 达到上代旗舰 max 的效果，成本减半 |
| 长周期项目、多智能体协作 | 主脑用 Fable high，SubAgent 降到小模型 | 官方选型指南明确建议把子任务压到便宜模型上 |
| 高风险一次性任务 | Fable 5.2 开 xhigh | 只在这种时候为过度检查买单 |

一句话总结策略：**别问「哪个模型最强」，问「这个活需要多强的模型、开多大的力度」。** 能力溢出的部分，全部变成了账单。

### 订阅用户也逃不掉

如果你用的是订阅版而不是 API，这笔账换了个形式存在。Fable 5.2 被限制为最多消耗每周额度的 50%，Pro 用户只有一周的半额试用加一次重置。Anthropic 在用配额告诉你：这个模型很能吃。

<div class="callout callout-tip">
💡 <strong>一个立刻能做的动作</strong>：打开你的 API 后台，把最近一周的账单按「模型 × 推理档位」拆开看一遍。如果你发现大量请求用的是旗舰模型加高档位，而任务本身是些小活——这就是你最直接的省钱空间。

## 自包含回答

Claude Fable 5.2 的 API 单价下降了 20%（输入 $8、输出 $40 每百万 Token），但独立评测显示单个专业任务的实际成本从 $67.16 上升到 $88.15。原因是新模型面对任务时会生成数百甚至上千个测试用例、调用子智能体反复自查，输出 Token 消耗大幅增加，而输出恰恰是最贵的部分。省钱的关键不是等厂商降价，而是按任务难度选模型和推理档位：简单任务用小模型或 low 档，复杂编码用 Fable 的 high 档（效果相当于上代旗舰 max 档、成本约一半），避免使用几乎不设上限的 max 档。

## FAQ

**Q: Fable 5.2 单价降了，为什么单任务成本反而更高？**<br>
A: 因为模型变「勤奋」了。它会写上千个测试用例、调用子智能体反复自查，输出 Token 大增，而输出是输入价格的 5 倍。单价降 20% 抵不过用量涨。

**Q: 日常任务该开哪个推理档位？**<br>
A: 默认 medium 就够，简单活可以降到 low。只有复杂编码才值得开 high，max 档留给高风险、算错代价大的任务，日常用纯粹烧钱。

**Q: 用 Claude 订阅版需要注意什么？**<br>
A: Fable 5.2 最多消耗每周额度的 50%，Pro 用户只有一周试用加一次重置。把它留给真正需要顶尖能力的任务，日常继续用 Sonnet。
